# Web 视觉重构方案

## 目标与范围

通过页面布局、对话组织、材质层次和动画反馈，让 Paimon 获得明显的新视觉效果，同时保留 Apple 设计语言与现有渐变背景。

- 工作分支：`feat/web-visual-redesign`。
- 本文记录已确认的实施方案，各阶段进度见文末。
- 产品代码修改范围限定为 `src/web/`；根目录 `package.json` 和 lockfile 用于添加前端 Motion 依赖，测试和设计文档随实现更新。
- 数据来源限定为现有历史消息、实时消息、工具执行事件和实例状态。
- 沿用现有颜色组、`mist` / `aurora` / `ember` 背景以及亮暗主题；替换颜色组须说明来源并经用户确认。
- 每阶段完成后等待用户审阅；每次 Git 提交与推送须由用户明确指示。

## 设计依据

已阅读的 Apple 官方指导：

- [Apple Design](https://developer.apple.com/design/)
- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
- [Color](https://developer.apple.com/design/human-interface-guidelines/color)
- [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)
- [Motion](https://developer.apple.com/design/human-interface-guidelines/motion)
- [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)
- [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)

采用这些共同原则：

- 玻璃材质集中用于导航和控制区域，正文以阅读清晰度为优先。
- 功能区域与内容区域通过层次、间距和局部材质建立关系。
- 工具栏按照功能分组，控制数量适应窗口宽度。
- 中性色用于大部分文字和辅助控件；强调色用于选中状态和主要操作。
- 状态通过文字、图标和动画共同表达。
- 同时考虑亮暗模式、对比度、键盘操作和减少动态效果的设置。

现有视觉参考见 [macOS 26 Design Tokens](macos-26-tokens.md)；Mermaid 继续遵循 [Mermaid 视觉主题](mermaid-theme.md)。

## 页面布局

### 实例侧栏

- 左侧采用单个完整玻璃面板，使用现有 `glass-panel`、`--panel-bg` 和 `--panel-border`，全局入口与实例列表共同位于其中。
- 页眉展示 Logo，首页与设置横向排列；新建按钮位于实例标题右侧，连接信息位于机器与实例数量旁。
- 按 Edge → 实例两级组织列表，保留 Edge 排序、复制以及实例选择、状态和退出操作。
- 实例列表独立滚动，页眉、标题、新建和连接信息保持可见；右键与长按行为继续可用。
- 选中项使用现有 `--fill-secondary` 轻量填充，控件通过 hover、按下和聚焦反馈表达交互。
- 渐变透过半透明侧栏呈现，并在侧栏周围与右侧内容区域保留可见空间。
- 小屏幕侧栏使用可用宽度，保留相同的顶部入口与实例列表；对话页面继续提供返回入口。

### 右侧全宽顶部栏

- 顶部栏横向铺满右侧对话区域，起点位于左侧列表右边缘之后。
- 顶部栏与左侧列表之间保留间距，内部保留统一的左右内边距。
- 左侧展示实例标题、目录和 Git branch，右侧保留 session 操作。
- 顶部栏沿右侧区域全宽共用一个 `header-material` 半透明容器，实例信息与 session 操作分别位于左右两侧；渐变背景继续可见。
- 正文继续居中并限制阅读宽度；顶部布局宽度独立于正文宽度。
- 小屏幕保留返回入口，目录和 Git branch 按可用空间展示；操作区保持清晰的点击目标。
- 顶部背景仅负责保证标题和控件可读，填充与模糊强度通过视觉检查确定。

### 渐变可见性

- 页面渐变在侧栏周围与对话正文周围持续可见，并透过侧栏的半透明材质呈现。
- 回复容器采用大圆角矩形，以浅中性色轮廓、轻量半透明填充和留白表达范围；容器周围与内部继续可见渐变。
- 顶部栏和输入区的材质须在三种背景与亮暗模式下检查。
- 具体透明度、模糊强度、圆角与阴影根据实际画面调整。

### 参考页面的使用方式

用户提供的 HTML 对以下结构具有参考价值：发送者名称、回复内部的执行摘要、内容下方的操作与时间，以及输入区底部的紧凑工具栏。

Paimon 继续使用现有颜色与材质体系，参考页面用于理解信息组织和交互层次。容器大小、填充透明度和动画按照本项目的阅读场景确定。

## 对话组织

### 回复分组

- 用户消息单独展示。
- 一条用户消息之后、下一条用户消息之前的 agent 内容组成一个回复容器。
- 此范围为基于消息顺序的展示分组，其定义与历史加载保持一致。
- 最新回复通过实时事件持续补充；实例切换和 session 切换时重置相关页面状态。
- 分组覆盖多条 assistant 消息，并保留各条消息与 content block 的原始顺序。
- `compaction` / `branch_summary` 保持系统事件身份及所在顺序，展示转换须保留其摘要内容。
- 缺少前置用户消息的历史内容保持可见，按已有内容顺序展示。
- 用户消息保留独立身份；回复组的标题和内容共同表达其归属。
- 外层采用 24px 大圆角矩形，使用现有 `--separator` 与 `--fill-quaternary`，正文及各个执行汇总共同位于其中。
- 整组回复默认展开正文，并提供独立的展开／收起入口；收起后保留 agent 标识、时间入口和状态摘要。
- 整组回复和内部执行汇总分别保存展开状态；重新展开整组回复后保留内部汇总的用户选择。
- 工具状态更新、正文生成和任务完成均保持用户选择的展开状态。
- 长回复采用页面正常滚动，代码与表格根据内容需要提供横向滚动。
- 内容增加时保持容器起点稳定，阅读位置随现有底部跟随条件管理。

### 连续执行区域

- 连续工具调用进入一个执行汇总；跨 assistant 消息的连续调用也可进入同一组。
- 正文出现时结束当前执行区域；后续调用建立新的汇总。
- 典型顺序：工具汇总 A → 正文 A → 工具汇总 B → 正文 B。
- thinking 收纳到对应的执行区域，保留自身标识和发生顺序。
- 只有 thinking 的执行区域也支持查看内容。
- `toolResult` 按 `toolCallId` 配回对应工具，作为结果更新参与展示。
- 用户消息及系统事件形成明确的分组边界。

### 汇总与详情

- 每个执行区域默认收起，以汇总形式展示；点击后展开对应列表，再次点击收起。
- 汇总显示“x 个工具执行中”“x 个工具执行完成”等数量与状态；混合状态分别表达进行中、完成和失败数量，终止保留明确提示。
- 工具数量按照独立 `toolCallId` 计算，thinking 单独标识。
- 展开后显示对应工具列表及 thinking；点击具体工具打开现有类型的详情弹窗。
- 正文直接展示，保持其原始内容与先后顺序。
- 保留运行中部分结果、错误、工具耗时、bash timeout 和历史结果详情。
- 流式更新与最终消息转换保持稳定 key，保留用户展开状态和已打开弹窗。
- 用户主动展开／收起后，后续工具状态和正文更新保留该选择。
- 收起只影响执行过程的可见性，工具继续更新状态并提供详情。
- 只有 thinking 的汇总显示对应文字，工具数量保持真实值。
- 较多工具展开后沿页面排列，工具条目采用紧凑行布局，名称、参数摘要、状态与耗时各有明确位置。
- 历史结果缺少运行耗时或状态信息时，仅展示已有信息。
- 错误提示和重新编辑入口在回复中保持可见，执行汇总准确表达失败和终止状态。

### 时间信息

- hover 或键盘聚焦时展示对应消息发生时间。
- 历史内容优先使用消息已有时间；实时内容使用现有事件携带的时间。
- 分组展示须保留内部消息的时间归属。
- 小屏幕提供触摸查看入口；缺少时间的数据保持内容可见。
- 回复组的时间入口可展示首次与最后一次消息时间；内部消息继续保留自己的时间。
- 日期、时间与时区的展示使用浏览器提供的格式化能力，并与界面语言一致。
- 时间显示为辅助信息，其出现保持正文布局稳定。

## 输入区与运行反馈

### 输入区

- 输入区采用单个 24px 圆角 `composer-surface`，使用现有 `--material-thin` 保留局部悬浮与玻璃层次。
- 上方提供文字输入与图片预览空间。
- 底部紧凑工具栏统一组织图片、模型、thinking level、上下文用量和压缩操作。
- 发送／停止按钮位于右侧，保持主要操作的视觉重点。
- 上下文提供紧凑百分比和完整用量弹层；压缩后 tokens 暂缺时，保留窗口大小并表达等待更新状态。
- 保留输入草稿、IME、Enter / Shift+Enter、图片上传和粘贴、重新编辑等交互。
- 小屏幕减少常驻文字，同时保证点击区域和控件可用性。
- 工具栏的左侧组织输入相关选项，右侧展示发送／停止；上下文读数与压缩操作保持相邻。
- 输入容器宽度达到 640px 时常驻 thinking 与压缩操作；较窄时使用更多选项菜单，发送／停止始终位于右侧。工具栏按钮在桌面至少具有 32px 高度，触摸设备中至少为 44px。
- 更多选项直接展示共用的 `ThinkingOptions`，并将完整上下文用量与压缩操作放在一起；选项选择与 Esc 关闭后恢复入口焦点。
- 图片预览和多行输入自然增加输入区高度，继续通过尺寸观察调整消息区域间距。
- 输入聚焦通过现有强调色和轻量边缘反馈表达，新增 UI 文本同时提供中文与英文。

### 状态位置

- 运行／压缩反馈位于最新回复附近及当前执行汇总中。
- 连接信息保留在导航或顶部功能区域。
- 工具执行状态与实例整体状态分别处理。
- 使用现有工具事件更新数量、部分结果、完成与错误。
- 使用实例 `streaming` / `compacting` / `idle` 表达整体运行状态；保持现有任务完成通知语义。
- 尚无 assistant 内容时也提供可见的运行反馈。
- 当前正在思考时显示 thinking 提示；工具正在执行时显示工具状态；整体运行仍在继续且暂缺具体阶段信息时使用通用运行提示。
- 回复区域只保留一个主要运行提示，工具条目各自显示局部状态。
- 压缩提示占用稳定位置；状态变化尽量保持内容区域高度稳定。
- 运行提示持续提供文字含义，停止、失败和完成时同步结束对应动画。

### 系统事件

- 上下文压缩记录采用轻量系统事件卡片，展示图标、标题和可用时间。
- 点击查看完整摘要，与实时压缩提示共享视觉语言。
- 分支摘要采用一致的系统事件样式。
- 使用现有中性色、边框和文字层级。

## 动画

- 等待或思考：轻量呼吸／流动效果与明确文字提示。
- 工具执行：汇总中的动态指示与数量更新。
- 压缩：独立状态提示与加载动画。
- 完成：运行指示平稳结束，过渡到最终摘要。
- 展开／收起：高度与透明度平滑变化，保持当前阅读位置。
- 工具详情、选择器与相关弹层：统一进入和退出节奏。
- 控件：适度的 hover 与按下反馈。
- 内容更新过程中保持既有内容稳定，动画集中于变化区域。
- 历史刷新和向上追加时直接展示已有内容；新交互与实时状态变化使用短动画。
- 工具计数和时间信息的更新保持布局稳定，正文流式增长保持阅读连续。
- 优先使用 `transform` / `opacity`，限制持续动画与重复布局计算。
- `prefers-reduced-motion` 下提供静态状态，完成、终止或卸载后清理持续动画与计时。

### 工具详情弹窗

- 桌面和宽屏平板使用居中圆角弹窗：遮罩淡入，详情面板轻微缩放并淡入；关闭时采用一致的退出方向。
- 手机使用从底部进入、接近全屏高度的 sheet，保留顶部圆角、少量背景和 Safe Area。
- 手机 sheet 打开时向上进入、关闭时向下退出，配合遮罩淡入／淡出。
- 标题与关闭按钮固定，详情内容独立滚动；尺寸跟随可见视口。
- 手机支持下滑关闭，协调关闭手势与内容滚动，代码的横向滚动和内容选择保持可用。
- 初步节奏：打开约 200ms、关闭约 150ms；这些参数为项目建议，通过实际体验调整。
- 内容打开后即可操作，快速关闭、再次打开及切换工具详情均须正常响应。
- 动画生命周期覆盖实际卸载边界，退出完成后移除弹窗。
- 使用稳定的工具身份，工具结束和最终历史消息更新保持已打开详情及其阅读位置。
- 弹窗提供 dialog 语义、Esc、焦点循环、背景交互限制和关闭后的焦点恢复。
- 遮罩及面板退出期间保持交互层次一致，退出完成后恢复原页面操作。
- 大图预览继续保留主题切换、尺寸模式、阅读位置与焦点行为。

### 动画实现

- 使用 Motion for React，覆盖弹层进出、折叠区域、状态过渡与可中断动画。
- 官方文档：[Motion for React](https://motion.dev/docs/react)、[AnimatePresence](https://motion.dev/docs/react-animate-presence) 和 [LazyMotion](https://motion.dev/docs/react-lazy-motion)。
- 弹层使用稳定 key，并将管理退出动画的组件保留在实际卸载条件之外。
- 使用 `LazyMotion`、同步 `domAnimation` 功能和 `m` 组件管理折叠动画，构建后检查实际入口体积和静态依赖。
- 简单 hover、颜色过渡和持续加载指示可以由 CSS 管理；组件进出与折叠动画统一管理其生命周期。
- 流式文字与历史追加采用局部更新，整体页面布局动画须与滚动管理共同验证。
- 通过根目录 `package.json` 和 lockfile 添加前端 Motion 依赖，产品实现位于 `src/web/`。

## 尺寸与间距

- 以 CSS px 定义 Web 尺寸，Apple 的平台尺寸用于设计参考。操作区域根据输入方式调整，使用 `pointer: coarse` 管理触摸规格。
- 桌面 regular 按钮与字段采用 36px，icon 按钮采用 32px，compact 按钮采用 28px；badge 可见尺寸为 24px。触摸设备中常规控件至少为 44px，badge 与 inline 入口通过独立区域提供至少 44px 宽高。
- 创建与取消、开始与取消保持相同尺寸；强调色和填充表达主要操作。发送、停止、上传、压缩及导航图标使用共用 icon 规格。
- 顶部栏内部最小高度为 44px，上下内边距合计 16px；保留全宽玻璃材质、目录与 Git branch。桌面侧栏在 `md` 为 240px、`lg` 为 260px，页眉、标题与 Edge 分组采用紧凑间距。
- 实例条目上下各 6px 内边距，名称采用 14px／20px，模型采用 11px／14px；进度条前间距为 4px，底色使用内容区全宽，填充长度保持真实用量；实例操作的位置仅在文字行预留。条目间距为 2px。
- 回复内容项间距为 8px，底部内边距为手机 12px、桌面 16px。消息时间在正文旁边独立排列，触摸设备保留入口间距；Markdown 正文保持 14px／22px。
- 执行汇总、工具条目和 thinking 入口在桌面至少为 32px，触摸设备至少为 44px。标题与折叠范围保持原有顺序及身份。
- 输入框单行最小高度为 48px，上下内边距合计 22px，桌面采用 14px／22px 字体与行高，左右内边距为 20px；工具栏底部内边距为 12px，图片预览为 56px，移除入口采用 badge 规格。
- 设置的主题、背景、语言与通知共用 compact 分段选项，桌面高度为 28px，触摸设备至少为 44px；背景在文字旁使用 16px 彩色标记，保留现有颜色组与原始 value。
- 表单内容的内边距与分组间距均为 16px；多行字段最小高度为 88px。菜单、设置、代码与图表操作区采用共用紧凑规格，Safe Area 与独立滚动保持可用。
- `Density.test.ts` 使用 PostCSS 检查尺寸声明及触摸规则。真实尺寸、文本阅读、点击范围和整体效果由用户检查。

## 实施顺序

1. **对话展示模型与测试**：在前端建立回复分组和连续执行区域，保留 entries 作为历史分页及工具结果的原始数据来源。
2. **对话组件**：实现独立汇总、工具列表、thinking、时间展示、系统事件卡片及运行反馈，复用详情渲染能力。
3. **布局与输入区**：实现整体玻璃侧栏、右侧全宽顶部栏、紧凑工具栏和新输入区，渐变可见性由用户在浏览器中检查。
4. **动画与响应式**：统一交互节奏，完善滚动、小屏幕、Safe Area、键盘与减少动态效果支持。
5. **补全页面、弹层与控件样式**：建立公共按钮、表单、菜单条目和状态提示，覆盖新建实例、压缩、session、选择器、设置、登录、内容操作、辅助入口与特殊状态。
